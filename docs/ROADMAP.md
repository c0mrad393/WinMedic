## ეტაპი 2 — არქიტექტურა: ინკრემენტული, არა big-bang

**გადაწყვეტილება (2026-09-04): 44,000 ხაზის ერთბაშად დაშლა არ ხდება.**

თავდაპირველი გეგმა იყო მთელი მონოლითის მოდულებად დაშლა. ეს უარვყავით: ეს კვირების სამუშაოა, რომელიც ნულ ხილულ შედეგს იძლევა და სამუდამოდ კლავს `git merge upstream/main`-ს, რომლითაც upstream-ის bugfix-ებს ვიღებთ.

სამაგიეროდ:

- ყველა **ახალი** კოდი `Modules/*.ps1`-ში იწერება დღიდან პირველი
- `WMT-GUI.ps1` მხოლოდ dot-source-ს აკეთებს (`WINMEDIC MODULE LOADER` მარკერებს შორის)
- არსებული ფუნქცია მოდულში მაშინ გადადის, როცა ისედაც უნდა შეეხო
- `PS2EXE/Build-Exe.ps1` build-ისას მოდულებს სკრიპტში ჩააკერებს, ანუ ერთფაილიანი `.exe` იგივენაირად მუშაობს

CI ახალ კოდს უფრო მკაცრად ამოწმებს: `Modules/`-ში **ნებისმიერი warning** build-ს ვარდნის, მონოლითი კი მხოლოდ error-ებზეა შემოწმებული. ასე ვალი ნელ-ნელა მცირდება იმის ნაცვლად, რომ ერთბაშად გადავიხადოთ.

## Upstream-თან მუშაობა

განახლებების ჩამოსატანად:

```bash
git fetch upstream
git log --oneline HEAD..upstream/main    # რა შეიცვალა
git merge upstream/main                   # ან cherry-pick კონკრეტული commit-ები
```

სანამ ეტაპი 2 დასრულდება, merge შედარებით უმტკივნეულოა. მის შემდეგ ჯობია cherry-pick-ი ან ხელით პორტირება.
